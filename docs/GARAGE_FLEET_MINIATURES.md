# Live fleet miniatures

The five fleet rows use the same prepared Rocket, H2, S4, U6 and V8 GLB models as the playable garage cars. They are not illustration assets or animated sprites. `RoadRenderer.createShowcaseVehicle` creates the same authored geometry and applies each owned vehicle's saved paint, rim, glass and compatible parts. Unowned entries use stock appearance. Card selection and acquisition remain separate actions; hover never changes the save.

`FleetMiniatures` borrows the existing game WebGL renderer and reflection environment. One small studio scene renders the actual vehicle group at its current yaw through two shared bounded 320 × 180 targets (HDR scene and byte presentation). Canvas2D presents the resulting pixels in the accessible catalog button. There is no independent renderer/context per card. Hover and keyboard focus turn the vehicle smoothly by 0.86 radians over 0.85 seconds; exit eases back. Touch selection plays the same finite turn then returns. Reduced motion retains a static render of the real model.

Only intersecting rows are prepared and rendered. A settled card reuses its last pixels; the entire feature has a global maximum of 12 logical snapshots per second, with only the active model and one returning model eligible for motion. Render work is paused behind settings, account/payment/ad pauses, hidden pages and the portrait orientation gate. Source geometry, textures and environment are borrowed and never disposed by this feature. Its own material instances, targets and presentation resources are released when replaced/disposed. Async readbacks carry exact canvas/loadout/profile-generation ownership, preventing old frames appearing on a new profile or selection. A real failure shows an unavailable-preview label, not a substitute vehicle.

The studio uses an explicit HDR/ACES presentation pass so highlights are not clipped by an ordinary byte render target. Its extra draw/targets are bounded and shared, not free: the detailed Rocket costs substantially more triangles per snapshot than a traffic-derived car. Native QA uses software WebGL and does not establish real-device FPS.

Validation: `node --test tests/garage-fleet-miniatures.test.mjs tests/garage-ui.test.mjs tests/garage-integration.test.mjs`; native visual/control proof: `CHROME_BIN=... SOFTWARE_WEBGL=1 node scripts/garage-fleet-miniatures-qa.mjs` (omit SOFTWARE_WEBGL for normal hardware). The QA uses a private local inventory, real DOM controls and production models, never a platform account or live purchase.

Final local verification: 806 tests pass, source/import checks report zero errors and the production build succeeds. Native desktop 1440 × 900 and landscape 844 × 390 checks cover all five vehicles, saved graphite H2 appearance, actual hover/focus yaw, two successive touch selections and return, scroll-lazy rendering, and portrait pause. A separate DPR=2 phone capture uses the game's bounded 1266 × 585 main drawing buffer; miniature targets remain 320 × 180, with no viewport cropping. Error logs are empty. The controller and module tests additionally cover account generations, overlays, async failure, unsupported HDR, target state and context restoration.
